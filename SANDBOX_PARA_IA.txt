================================================================================
SANDBOX REMOTO PARA IA — Navegador-ping / Bebo AI Host
Documento de integración (pásale este archivo a la IA)
================================================================================

Tienes acceso a un SANDBOX remoto: una shell Linux real por WebSocket.
Cada "project" es un directorio aislado. Puedes ejecutar comandos, crear
archivos, instalar dependencias y lanzar procesos dentro de ese proyecto.


--------------------------------------------------------------------------------
1. CÓMO CONECTARTE
--------------------------------------------------------------------------------

URL (producción / Render):
  wss://<HOST_DEL_SERVICIO>/?project=<NOMBRE_PROYECTO>

URL (local / Docker):
  ws://127.0.0.1:8765/?project=<NOMBRE_PROYECTO>

Autenticación (elige una):
  • Header HTTP:  Authorization: Bearer <BEBO_SHELL_TOKEN>
  • Query string:  &token=<BEBO_SHELL_TOKEN>

Reglas del nombre de proyecto:
  • Solo: letras, números, guión (-) y guión bajo (_)
  • Ejemplos válidos: demo, app1, mi_proyecto, test-01
  • NO uses rutas, puntos, espacios ni ../

Si el proyecto no existe, se crea automáticamente el directorio.


--------------------------------------------------------------------------------
2. PROTOCOLO DE MENSAJES (JSON)
--------------------------------------------------------------------------------

Tú envías al sandbox:

  Entrada de comandos / teclado:
  {"type":"input","data":"comando aquí\n"}

  Importante: casi siempre termina el "data" con \n (Enter).

  Redimensionar terminal (opcional):
  {"type":"resize","cols":120,"rows":40}

El sandbox te responde:

  Salida del proceso:
  {"type":"output","data":"texto que imprimió la shell\n"}

  Error:
  {"type":"error","error":"command_timeout"}
  {"type":"error","error":"command_too_large"}
  {"type":"error","error":"invalid_message"}
  {"type":"error","error":"invalid_utf8"}

También puedes enviar texto plano (sin JSON); se trata como input.


--------------------------------------------------------------------------------
3. QUÉ PUEDE HACER EL SANDBOX
--------------------------------------------------------------------------------

Entorno Linux (bash) con herramientas instaladas:

  • Shell interactiva: bash
  • Python 3 + pip
  • Node.js 20 + npm
  • Git
  • curl, herramientas básicas de sistema
  • Cliente PostgreSQL (psql) si hay DATABASE_URL
  • Chromium (para capturas vía browser_bot.js)
  • tmux (sesiones en background)

Capacidades típicas para una IA:

  1. Ejecutar comandos de terminal
  2. Crear y editar archivos (también bloques grandes)
  3. Instalar dependencias (pip / npm)
  4. Ejecutar programas Python/Node
  5. Git
  6. Servidores en background con tmux
  7. Capturas web con browser_bot.js

Directorio de trabajo:
  /workspace/proyectos/<NOMBRE_PROYECTO>


--------------------------------------------------------------------------------
4. LÍMITES
--------------------------------------------------------------------------------

  Por defecto NO hay límite de tamaño de comando ni de salida del proyecto
  (MAX_COMMAND_BYTES=0, MAX_OUTPUT_BYTES=0). Tampoco hay timeout de comando
  (COMMAND_TIMEOUT_SECONDS=0).

  Si el operador configura esos valores > 0, entonces sí se aplican.

  Siempre aplica:
  • Aislamiento con bubblewrap cuando está disponible
  • Trabajo dentro del directorio del proyecto
  • Hay red (curl, npm, pip, etc.)


--------------------------------------------------------------------------------
5. CÓMO DEBE USARLO LA IA (BUENAS PRÁCTICAS)
--------------------------------------------------------------------------------

1) Conéctate con token y project correctos.
2) Envía comandos terminados en \n y espera output.
3) Comprueba listo con: {"type":"input","data":"printf READY\\n\n"}
4) Puedes pegar archivos o comandos largos (sin tope por defecto).
5) Procesos largos: usa tmux o nohup &
6) Cierre 1008 = token o project inválido.


--------------------------------------------------------------------------------
6. DATOS QUE DEBE TENER LA IA
--------------------------------------------------------------------------------

  SANDBOX_WS_URL   = wss://<tu-servicio.onrender.com>
  SANDBOX_TOKEN    = valor de BEBO_SHELL_TOKEN
  SANDBOX_PROJECT  = nombre del proyecto

URL:
  {SANDBOX_WS_URL}/?project={SANDBOX_PROJECT}
  Header: Authorization: Bearer {SANDBOX_TOKEN}


--------------------------------------------------------------------------------
7. RESUMEN
--------------------------------------------------------------------------------

Shell Linux remota por WebSocket, autenticada, aislada por proyecto,
sin límites de tamaño por defecto, con Python/Node/bash/git/npm/pip.
